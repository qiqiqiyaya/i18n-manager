# 大数据优化

> 编辑器大数据量性能优化：从 `jsoneditor` tree 模式（全量 DOM 渲染）迁移到 Monaco Editor（虚拟化文本渲染），已实施。

## 背景

Schema/译文编辑器最初用 `jsoneditor` 库的 tree 模式。数据量大时（数千键 / 深层嵌套），tree 模式为每个节点创建独立 DOM 元素，导致页面加载卡顿、展开/收起响应慢、输入延迟。

**实测规模**：Schema 340 键（扁平）、单语言文件 ~467KB、根级节点 30-50（展开后约 340 叶节点）。

**根因**：`jsoneditor` tree 模式全量 DOM 渲染、无虚拟滚动。

## 方案（已实施）

迁移至 `@monaco-editor/react`：Monaco 虚拟化文本渲染，仅渲染可视区域的行。

- `MonacoEditor.tsx`：`@monaco-editor/react` 封装（`next/dynamic` SSR 安全）。
- `SchemaEditor`/`LocaleEditor`：Monaco JSON 模式 + RxJS 防抖解析。
- `ImportPreviewDialog`：Monaco `DiffEditor` 并排对比。
- 收益：无卡顿、粘贴自动格式化、折叠支持、内置 `actions.find` 搜索。

## 未来方向

1. **增量加载**：当前 `useProjectEditor` 加载所有语言文件；可改为按需加载（打开 Tab 时才加载）。
2. **Namespace Tab 拆分**：超大 JSON 按顶层 namespace 拆多个 Tab（`NamespaceTabs` 组件 + 按 namespace 过滤 + 保存合并）。
3. **Web Worker 解析**：自定义 JSON 解析/diff 计算移至 Web Worker，避免阻塞主线程。

## 关键设计约束

- 编辑器强制 `@monaco-editor/react`，任何方案不得替换。
- 旧 `JsonEditor.tsx`（jsoneditor 封装）已弃用但保留，可安全删除。
- 自动保存用 RxJS 防抖，不得用原生 `setTimeout`。
