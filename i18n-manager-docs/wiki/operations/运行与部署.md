# 运行与部署

> 单进程架构的部署与运维手册：部署流程、健康检查、常见问题排查、回滚流程。

## 架构概览

- 单进程 Node 服务（`server.ts`，经 `tsx` 运行）：Express 5 包装 Next.js，同一 HTTP server 挂载 Socket.IO。
- HTTP + WebSocket 同端口（默认 3000）；Socket.IO 路径 `/socket.io` 自处理，其余交 Next.js。
- 启动自动 `fs.ensureDirSync({DATA_DIR}/projects)`。
- `fix-async-storage.cjs` 经 `--require` 注入 `globalThis.AsyncLocalStorage`（Next.js 16 canary 兼容）。

## 部署流程

```bash
git pull && npm ci
cp .env.example .env.local    # 首次；按环境调整 PORT / DATA_DIR / NEXT_PUBLIC_WS_URL
npm run build
NODE_ENV=production npm run start:server
```

> ⚠️ `npm run start`（`next start`）仅启动 Next.js，**不含** Express/Socket.IO 协作层。生产需要实时协作必须用 `start:server`。

**PM2 示例**：
```json
{
  "name": "i18n-manager",
  "script": "node",
  "args": "--require ./fix-async-storage.cjs --import tsx server.ts",
  "env": { "NODE_ENV": "production", "PORT": "3000", "DATA_DIR": "./data" }
}
```

## 健康检查

- **HTTP**：`GET /` 返回项目列表页（200）。
- **WebSocket**：客户端能连上 `NEXT_PUBLIC_WS_URL` 并加入 `room:project-{projectId}`。
- **数据目录**：`{DATA_DIR}/projects/` 存在且进程有读写权限。
- **启动日志**：`> Server listening at http://localhost:{PORT}` 与 `> Data directory: {DATA_DIR}`。

## 常见问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 启动即退出，端口占用 | `PORT` 被占用 | 换 `PORT` 或释放端口 |
| 报 `AsyncLocalStorage` 错误 | `fix-async-storage.cjs` 未加载 | 确认启动命令含 `--require ./fix-async-storage.cjs` |
| 前端无法实时协作 | 只跑了 `start`/`dev` | 改用 `start:server` |
| WebSocket 连接失败 | `NEXT_PUBLIC_WS_URL` 不符 | 修正后重新构建（NEXT_PUBLIC_ 变量构建时烘焙） |
| 保存报锁冲突/写入失败 | proper-lockfile 互斥锁未释放 / 目录无写权限 | 检查 `{DATA_DIR}` 权限；清理残留 `.tmp`/`.lock` |
| 导入返回 409 | 检测到冲突需确认 | 前端确认后带 `confirmed=true` 重新提交 |
| Schema 保存被拒 | 时间戳冲突 | 客户端收到 `schema:rejected` 自动同步最新版本 |
| 删除语言返回 409 | 是项目最后一个语言 | 至少保留一个语言 |
| Express 5 路由报错 | 使用了通配符路径 | path-to-regexp v8 不支持通配符；用无路径 `use()` 兜底 |

> [!warning] ⚠️ 文档矛盾
> `[[raw/RUNBOOK.md|RUNBOOK.md]]` 的「键锁长时间不释放」行与 `LOCK_TIMEOUT` 环境变量描述的是**键级锁定**。
> **权威状态**：键级锁定已于 2026-08-09 移除，该行已过时（见 [[concepts/并发与冲突处理|并发与冲突处理]]）。

## 回滚流程

```bash
git checkout <上一稳定 tag 或 commit>
npm ci && npm run build
NODE_ENV=production npm run start:server
```

**数据回滚**：数据为本地 JSON 文件，回滚前备份 `{DATA_DIR}/projects/`；恢复某项目直接替换对应 `data/projects/{projectId}/` 目录（服务热读取，无需迁移）。

## 告警与升级

- 无内置告警；建议进程管理器配置崩溃自动重启 + 重启告警。
- 监控磁盘空间（数据写入 `{DATA_DIR}`）。
- 严重问题优先按回滚流程恢复，再排查根因。
